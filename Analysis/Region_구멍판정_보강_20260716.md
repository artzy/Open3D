# Region 구멍 판정 보강 (2026-07-16)

## 목표와 고정 요구사항

하나의 연결된 개곡면 region mesh를 freeze하기 전에 다음 세 신호를 함께
검사해 조기 commit으로 남는 구멍을 줄인다.

1. 기존 surface-cell `void_report`
2. mesh boundary loop topology
3. TSDF 관측 weight coverage

RealTime과 Online 경로에서 같은 `ObjectMeshPipeline.h` 구현을 사용하고,
CPU/CUDA/SYCL에서 동작해야 한다.

## 구현 결정

### Boundary loop

- edge 사용 횟수 1은 boundary, 2는 manifold interior, 3 이상은
  non-manifold로 집계한다.
- triangle connected component별 boundary graph를 만든다.
- 모든 정점 차수가 2인 boundary component만 closed loop로 본다.
- 각 surface component에서 둘레가 가장 큰 loop는 외곽 경계로 간주한다.
- 나머지 closed loop 중 `max(0.03 m, 4 * voxel_size)` 이상을 내부
  hole loop로 판정한다.

### TSDF weight 비교

raw HashMap weight buffer를 직접 읽지 않는다. 동일 candidate block에서:

- weight `>= 1`: 한 번 이상 관측된 전체 TSDF 표면
- weight `>= mesh_weight_threshold` (기본 3): 신뢰 표면

각 표면을 `max(1 cm, 2 * voxel_size)` cell로 양자화하고
`reliable_cells / observed_cells`를 coverage로 계산한다. 이 방식은 기존
VoxelBlockGrid public API를 사용하므로 device별 weight dtype/버퍼 배치를
건드리지 않는다.

## Gate 기본값

| 항목 | 기본값 |
|------|--------|
| 최소 hole loop 둘레 | 0.03 m (또는 4 voxel 중 큰 값) |
| 허용 내부 hole loop | 0 |
| 최소 TSDF weight coverage | 0.70 |
| flush 시 coverage 완화 | 기본값의 0.85배 |
| open boundary chain | 진단 로그만 기록 |
| non-manifold edge | 허용하지 않음 |

관측 예:

```text
holes=58/330 max_hole=2.261m open_chains=3 non_manifold=0
tsdf_weight=0.94 (33877/35900)
```

기존 cell void는 `0.00`이었지만 내부 boundary loop를 검출해 commit을
보류했다. weight coverage는 높으므로 이 사례는 단순 저관측보다 mesh
topology 결손 가능성이 높은 것으로 분류된다. 기본값이 내부 loop 0개를
요구하므로 품질 우선 동작이며, 의도된 opening이 있는 대상은
`--region_max_hole_loops`로 완화한다.

`open_chains`는 닫힌 내부 hole의 근거가 아니므로 단독 hard reject에는
사용하지 않는다. boundary graph 이상을 진단하는 로그로 유지한다.

## 위험과 완화

- 의도된 내부 opening도 hole로 볼 수 있다. `--region_max_hole_loops`로
  허용량을 조정할 수 있다.
- weight 1/3 표면을 각각 추출하므로 candidate 판정 비용이 증가한다.
  region worker에서만 실행하고 public extraction API를 재사용한다.
- 여러 disconnected triangle component는 component마다 가장 큰 boundary를
  외곽으로 처리해 서로의 외곽을 hole로 오인하지 않는다.
